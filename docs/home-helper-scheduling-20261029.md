# 9600 복귀 후 헬퍼 스케줄링 검증 및 운영 설정

2026-10-29. 양자화, 하드웨어, CPU 오버클럭은 변경하지 않았다. 원래 Claude qshort 하네스로 측정했다. 아래 각 비교는 같은 후보 바이너리에서 설정만 바꿨으며 각 arm 두 회 평균이다.

| 실험 | 설정 | chat tok/s | code tok/s |
|---|---|---:|---:|
| CPU 작업 분할 | 스레드당 4개 | 38.35 | 34.30 |
| CPU 작업 분할 | 스레드당 1개 | 38.40 | 34.30 |
| CPU/GPU 동시 실행 | OFF | 38.30 | 34.25 |
| CPU/GPU 동시 실행 | ON | 38.35 | 34.35 |

두 변경 모두 유의미한 개선을 입증하지 못했다. 운영 헬퍼는 원본으로 복원했고 소스 변경도 되돌렸다. 재현용 변경은 `experiments/helper-scheduling-20261029.patch`에만 보관했다.

## 관측과 검증

- 동시 실행 비교에서 91,952개 요청 중 CPU/GPU 혼합 요청은 53개(0.05764%)였다. CPU 전문가 123,397개가 73,657개 요청에서 실행되었다. 따라서 GPU를 기다리는 동안 CPU를 겹치는 최적화의 적용 범위가 매우 작다. 소스상 가능한 GPU 담당 호출 스레드의 부재를 전체 CPU 병목으로 해석하면 안 된다.
- ON에서 16회 동기 GPU 결과와 비트 단위 동일성을 검사해 통과했다. CPU 완료 후 GPU 대기 합계는 0.046ms였다. 두 arm의 전문가/요청 수가 같았고 대응하는 greedy 해시도 같았다.
- CPU 작업 분할은 행별 계산과 최종 합산 순서를 유지했다. 네이티브 CPU 분할/정확 행 범위 테스트도 통과했다.
- 작업 분할 첫 실행은 정상 T2 측정 두 회 후 검증기의 과거 T3 고정 조건 때문에 중단되었다. 검증기를 `T=fixed+1`로 고쳐 보존된 baseline을 재검증했고, 두 번째 실행에서는 미측정 후보만 측정했다.
- 동시 실행의 CPU 시간 계측 경계는 기존 CPU tail과 다르므로 직접 성능 비교에는 전체 하네스 결과를 사용했다.
- B650 복귀 부팅의 커널 로그에서 PCIe Bus Error/AER error/NVIDIA Xid는 발견되지 않았다. 이 플랫폼은 해당 root AER 카운터 파일이 없어 카운터 0을 측정했다는 의미는 아니다.

## 운영 반영

이전 검증에서 선택한 MTP 초안 1개, T2 검증, window fetch reuse 설정을 상시 설정에 반영했다. 원본 CPU 헬퍼 6스레드를 유지했다.

- 설정: 메인 `~/fn/maya-config/iq4-kohane5200.json`
- 엔진: `~/fn/bin-test/maya-t2-reuse-20261028`
- 시작: `MAYA_NET=1 ~/fn/start-maya-kohane5200.sh`
- 원본 설정 백업: `~/fn/codex-fast-production-20261029/original-config.json`
- 운영 설정 적용 후 하네스 1회: **chat 38.9, code 34.2 tok/s**.
- 결과/선택 설정: `~/fn/codex-fast-production-20261029/` 및 로컬 `maya-fast-production-20261029/codex-fast-production-20261029/`.

50 tok/s는 아직 달성하지 못했다. 현재 수치에서 토큰당 시간을 chat 약 22.2%, code 약 31.6% 줄여야 한다. CPU 미세 스케줄링보다 CPU가 읽는 전문가 가중치와 메인 RAM→GPU 전송량을 줄이는 배치/경로 선택, MTP의 추가 비용 및 승인 토큰 수가 다음 검토 대상이다. 후속 확인: 헬퍼 초기화에는 사용 빈도 정렬 코드가 있지만 현재 프로세스는 USAGE 파일을 지정하지 않아 초기 점수가 모두 0이다. 따라서 stable sort가 층/전문가 순서를 유지하며 초기 GPU 헬퍼 배치는 앞쪽 층에 집중된다. 별도의 expert-profile은 각 층의 primary warm 순위를 정하며 이 전역 점수를 채우지 않는다. 이 구조를 바꾸면 호출 레이어 수와 RAM 중복 배치도 바뀌므로 실제 성능 개선은 별도 검증이 필요하다.
