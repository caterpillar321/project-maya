# T2 요청 선발송 후 헬퍼 분배 비용 재검증

9600/B650, `maya-early-route-20261029`, fixed1/T2, scratch3, fetch reuse 및 route ahead ON을 유지했습니다. 기존 비용 sweep은 MTP OFF 조건이어서 현재 검증 창의 연속 요청에서도 같은 값이 적절한지 다시 측정했습니다. CPU/RAM helper는 기존 바이너리와 6스레드/54GiB 그대로입니다. Claude qshort 하네스를 수정하지 않았습니다.

## 전문가당 CPU 비용 추정치

RTT=0.35ms, shared RTT=0.10ms를 유지하고 `MAYA_GLM_NET_COPY_MS`를 변경했습니다. 이는 CPU 클럭이나 실제 연산을 늦추는 옵션이 아니라 GPU/CPU 작업 분배 정책에 넣는 추정 비용입니다.

| 비용 ms | chat tok/s | code tok/s | chat RAM fetch/tok | code RAM fetch/tok |
|---|---:|---:|---:|---:|
| 0.16, 앞선 route-ON 2회 평균 | 39.35 | 34.30 | 40.05 | 54.70 |
| 0.20, 2회 평균 | 36.65 | 33.35 | 46.45 | 58.90 |
| 0.24, 2회 평균 | 35.55 | 31.60 | 50.75 | 65.90 |
| 0.16, 뒤 대조 1회 | 39.30 | 34.70 | 40.00 | 54.00 |

**0.20과 0.24는 채택하지 않았습니다.** 선택적 CPU 작업을 줄이는 정책에서 메인 RAM→GPU fetch가 증가했고 처리량이 낮아졌습니다. 뒤 대조에서는 원래 처리량이 돌아왔습니다. 이 비교로 CPU helper가 언제나 병목이 아니라고 단정할 수는 없지만, 현재 설정에서 CPU 일을 덜 보내는 방향의 비용 조정은 역효과였습니다.

모든 arm의 시작 배치는 pool 1,466 slots, main RAM 7,302 slots, remote cold 788개, optional copies 3,543개로 같습니다. 0.20/0.24/뒤 대조 총45요청의 route audit가 완결됐습니다. 정책 변화에 따라 실행 경로와 출력이 바뀔 수 있으므로 같은 토큰열의 고정 replay 비교는 아닙니다.

원자료: `maya-mtp-copycost-20261029/`, 메인 `~/fn/codex-mtp-copycost-20261029/`.

## 고정 호출 지연 추정치

후속은 전문가당 비용을 0.16으로 복구하고 `MAYA_GLM_NET_COPY_RTT`만 0.35→0.20ms로 변경하는 제한 비교입니다. shared RTT는 0.10 그대로입니다. 요청 선발송은 CPU 연산 자체보다 고정 호출 지연을 다른 작업과 겹칠 수 있게 하므로, CPU 비용 전반을 낮추는 것보다 좁은 가설입니다.

PCIe 비용 0.256 기준, 필수 CPU 작업이 없고 모든 RAM 전문가의 복사본이 있는 경우, RAM 전문가 5개/8개인 요청에서 선택적 CPU 전문가 수가 각각 2→3/4→5로 늘어납니다. 이미 mandatory CPU 작업이 있는 shared 요청의 정책은 바뀌지 않습니다. 실제 처리량 효과는 별도 결과로 판단합니다.

측정 결과 RTT=0.20은 chat **39.3/39.1**, code **34.6/34.4 tok/s**, 평균 **39.2/34.5**였습니다. 기존 route-ON의 39.35/34.30과 비교해 chat은 낮고 code는 소폭 높았지만 측정 변동 범위와 겹칩니다. 후보 20요청의 route audit는 모두 완결됐습니다.

16.5K 입력의 첫/반복 decode는 기존 33.8/35.0, 후보 33.4/35.1 tok/s였습니다. 출력 길이가 기존 225/225, 후보 219/219로 같지 않아 전체 wall time을 같은 작업의 가속률로 비교하지 않습니다. 첫 프리필은 각각 12.7115/12.7350초였습니다.

**RTT 0.20도 채택하지 않았습니다.** 최종 선택은 MS=0.16, RTT=0.35, shared RTT=0.10이며 요청 선발송만 ON입니다. 복사량의 감소만으로 처리량 개선을 주장하지 않습니다. 원자료는 `maya-mtp-rtt-20261029/`, 메인 `~/fn/codex-mtp-rtt-20261029/`입니다.
